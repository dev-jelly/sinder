# Sinder 0.3 사용성·구조 리뷰

검토일: 2026-09-12. macOS를 우선으로 개선하며 Windows용 경로·단축키·패키징 구조를 유지한다.

## 설계 기준

[Apple의 도구 막대 지침](https://developer.apple.com/design/human-interface-guidelines/toolbars)은 주요 작업의 우선순위, 익숙한 아이콘, 간결한 제목과 과밀하지 않은 그룹 구성을 권장한다. [Windows 레이아웃 지침](https://learn.microsoft.com/en-us/windows/apps/design/layout/)은 창 크기에 맞춰 사용할 수 있는 영역을 조정하는 접근을 제시한다.

이를 파일 관리자에 적용해 장식과 반복 설명을 줄이고 파일 이름, 현재 위치, 선택 대상과 작업 상태를 우선한다. 시스템 글꼴과 기존 아이콘을 유지하며 라이트·다크 테마의 대비와 키보드 포커스를 함께 다룬다.

## 코드 정리

- `workspace.ts`에서 패널 생성·탐색·재연결·갱신을 공유한다. 이동 기록과 활성 탭 처리의 반복 분기를 줄였다.
- `selection.ts`에서 선택 범위와 숨김 항목 정리를 분리해 UI 이벤트들이 동일한 규칙을 사용한다.
- 파일 작업 메뉴와 정렬 기준을 데이터로 정의한다. 대화상자 입력 필드도 공통 표현을 사용한다.
- 시스템 테마는 앱에서 실제 라이트·다크 값으로 해석한다. CSS의 중복 다크 색상 정의를 제거했다.
- 아이콘은 라이브러리의 공개 개별 내보내기를 통해 필요한 것만 불러온다. 전체 아이콘 선언 파일을 읽는 빌드 부담을 줄였다. React·아이콘 패키지는 빌드에만 사용하므로 배포 앱의 Node 의존성에서 제외했다.
- 미리보기는 `electron/preview.ts`로 분리했다. 입력 검증과 제한된 preload API는 명시적으로 유지한다.
- Electron 패키지에서 Node용으로 빌드된 선택적 `cpu-features` 모듈을 제외한다. SSH2는 이 모듈 없이 동작하며, 불필요한 네이티브 모듈 로딩을 피한다. 개발용 Node 테스트의 의존성은 유지한다.
- 설정 쓰기는 스냅샷별로 직렬화하고 임시 파일 쓰기·동기화 실패 시 정리한다. 원격 편집의 복구 상태 전이는 그대로 유지한다.
- 동일한 SSH 서버의 프로필 별칭도 하위 경로 복사를 방지한다. 서로 다른 프로필 사이 이동은 기존 스트리밍 경로를 유지한다.

실제 빌드한 화면 코드를 동일한 파일 목록으로 비교했다. 아래 측정은 Chromium renderer fixture이며 네이티브 창·SSH 검증과 구분한다. 라이트/다크, 1360×880/860×580, 단일/분할+정보 패널 조합의 16장 모두 가로 넘침과 화면 오류가 없었다.

최종 빌드와 TypeScript 검사가 통과했다. `npm test`의 39개 통합·단위 테스트, 실제 Electron E2E 6개, renderer 키보드 시나리오 4개가 통과했다. 실제 임시 OpenSSH 서버로 전송·이동·연결 취소·원격 편집 충돌·오프라인 저장·앱 재시작 복구를 검사했다.

Electron E2E는 작업 볼륨의 시작 지연을 분리하기 위해 동일한 빌드와 의존성을 내부 임시 디렉터리에 준비하고 실행했다. 초기 창 로딩에는 별도 대기 시간을 주며 일반 동작 검증은 15초 제한을 유지한다. 실행 명령은 `SINDER_E2E_APP=/tmp/sinder-e2e-app node node_modules/@playwright/test/cli.js test --timeout=300000`이었다. 사용자 설정과 실제 서버는 사용하지 않았다.

검사 중 미리보기 종료 후 포커스 복귀와 SSH 폼의 초기 포커스 오류를 발견해 공통 대화상자에서 수정했다. 수정한 빌드로 6개 Electron 시나리오 전체가 통과했다.

Windows 런타임, 실제 사용자 서버의 장시간 연결, 배포용 Apple Developer 서명·공증은 별도 검증 범위다. 이 리뷰에서는 해당 작업을 완료한 것으로 표시하지 않는다.
