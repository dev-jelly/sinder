# 로컬 SSH 설정 가져오기

Sinder 0.4는 사용자 홈의 `.ssh/config`를 읽는다. macOS에서는 `~/.ssh/config`, Windows에서는 사용자 홈 아래 `.ssh/config`다. 원본 설정과 키 파일을 수정하지 않는다.

**SSH 연결 추가**를 열면 자동으로 설정을 읽는다. **로컬 SSH 호스트**에서 별칭을 선택하면 연결 필드가 채워진다. **모두 추가**는 지원되는 호스트를 연결되지 않은 상태로 저장한다. 이후 사이드바의 호스트를 눌러 연결한다. 가져오는 동안 네트워크 연결이나 설정의 명령을 실행하지 않는다.

하나의 `Host`에 별칭이 여러 개 있으면 첫 번째 명시적 별칭을 대표 이름으로 사용한다. `Host *` 같은 패턴은 기본값으로 적용하며 별도 위치로 만들지 않는다. 다시 가져오면 이미 저장한 대표 별칭은 유지하고 새 항목만 추가한다. 기존 이름·시작 경로·인증 방식은 덮어쓰지 않는다.

## 적용되는 설정

- `HostName`, `User`, `Port`, `IdentityFile`, `IdentityAgent`. 사용자 생략 시 로컬 계정을 사용한다. 여러 키 중 존재하는 첫 파일을 선택하고, 명시한 키가 모두 없으면 첫 경로를 표시해 수정할 수 있게 한다. 키 내용이나 암호를 가져오기 결과에 포함하지 않는다.
- `Include`의 여러 경로·glob·중첩, 따옴표와 주석, 대소문자를 구분하지 않는 키워드, `Host`의 `*`·`?`·부정 패턴, 먼저 정해진 값의 우선순위. 상대 Include는 사용자 홈의 `.ssh` 기준이며 파일은 이름 순으로 읽는다.
- 홈 경로 `~`, `${환경변수}`, 키 경로의 `%d`·`%h`·`%n`·`%p`·`%r`·`%u`·`%%` 치환. 지시문마다 사용할 수 있는 치환 범위는 제한된다.
- 실행 파일과 인수로 구성한 `ProxyCommand`. 예: `~/.ssh/connect-proxy server %p`. 연결할 때 메인 프로세스가 로컬 설정을 다시 읽고, 셸 문자열을 조합하지 않고 실행 파일을 직접 시작한다. 연결 취소·종료 시 프록시도 종료한다.
- `ProxyJump`의 단일·여러 경유지. 시스템 OpenSSH의 `ssh -W`로 연결하고 목적지의 SFTP는 기존 ssh2 경로를 사용한다. 경유지는 로컬 키/agent로 비대화형 인증할 수 있고 기존 `known_hosts`에서 신뢰되어 있어야 한다. 비밀번호나 새 경유지 키 확인이 필요하면 먼저 터미널 SSH에서 설정한다.

가져온 연결의 호스트·사용자·포트·키는 저장한 값을 사용한다. 프록시와 agent 경로는 연결 시 로컬 설정에서 다시 읽는다. 원본에서 별칭을 삭제하면 우회해서 직접 연결하지 않고 오류를 표시한다. 새 연결 창에서 **직접 입력**을 선택하면 로컬 SSH 경로 연동을 해제하고 입력한 값으로 연결할 수 있다.

## 범위와 검증

OpenSSH 전체 설정을 그대로 실행하는 모드는 아니다. 조건식이 있는 `Match`(`Match all` 제외), 조건부 Include 안에서만 선언되는 호스트, 인증서 인증, 호스트 이름 정규화, 셸 파이프·리다이렉션을 포함한 ProxyCommand는 자동 가져오기에서 이유를 표시한다. 복잡한 프록시 명령은 실행 파일 스크립트로 분리해 사용할 수 있다. 시스템 전역 `ssh_config`, 다중 키 순차 인증, macOS Keychain 연동은 별도 지원 범위다.

Sinder의 서버 키 확인과 저장 정책을 유지한다. 대상 서버의 `StrictHostKeyChecking no`, `UserKnownHostsFile`, 연결 공유·포워딩·터미널 옵션은 Sinder 연결에 적용하지 않는다. 키 암호가 필요하면 연결 창에서 입력하며 저장하지 않는다.

설정 문법과 우선순위 기준: [OpenSSH ssh_config 공식 매뉴얼](https://man.openbsd.org/ssh_config).

자동 테스트는 임시 설정으로 Include·기본값·중복 방지·저장 실패·명령 미실행을 검사한다. 실제 임시 OpenSSH 서버를 사용해 ProxyCommand와 ProxyJump를 통한 SFTP 접근 및 프록시 취소·종료를 검사한다. Electron에서는 필드 자동 입력, 작은 창 조작, 연결 목록 저장과 중복 방지를 확인한다. Windows 실기와 사용자의 실제 서버 연결은 이 검증에 포함하지 않는다.
