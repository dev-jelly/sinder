# 구현 및 검증 상태

2026-09-23. 현재 버전은 0.5.2이다. 플랫폼 범위는 **macOS 우선, Windows도 지원할 구조**다.

## 0.5.2 Finder 복사 멈춤 수정

- Finder 수신 측이 유지하는 파일 쓰기 조정 안에서 Sinder가 같은 목적지를 다시 조정해 완료 콜백과 서로 기다리던 문제를 수정했다. 수신 측이 제공한 URL에 직접 전달하며 임시 폴더·원자적 게시·기존 파일 보호는 유지한다.
- 네이티브 테스트에 수신 측 쓰기 조정을 추가했다. 수정 전에는 완료 대기 시간 초과로 실패했고 수정 후에는 실제 SSH 파일·폴더 복사, 이름 충돌 보존, 원본 유지, 실패 전달 검사가 통과했다.
- 단위·SSH 통합 테스트 48개, Electron 시나리오 11개와 전체 빌드가 통과했다.
- `SINDER_DRAG_DIAGNOSTICS=1`로 드래그 세션 및 수신 요청 단계만 기록할 수 있다. 파일명·경로·자격증명은 기록하지 않는다.
- 배포 패키징은 완료됐지만 로그인 키체인이 잠겨 서명이 `errSecInternalComponent`, 공증 자격증명 조회가 `keychainLocked`로 중단됐다. 0.5.2 공개 배포와 설치본 교체는 아직 수행하지 않았다.
- 실제 Finder 창의 마우스 놓기 검증은 현재 UI 제어 환경에서 수행하지 못했다. 수신 계약을 재현한 자동 검증과 실기 검증을 구분한다.

## 0.5.1 Finder 원격 드래그와 배포 준비

- 숨김 파일은 `⌘⇧N`, 새 폴더는 `⌘⌥N`으로 변경했다. Option 키의 문자 변환과 새 창 단축키 충돌을 처리했다.
- macOS 원격 파일·폴더 드래그에 AppKit 파일 약속을 연결했다. Finder에서 놓은 뒤 SFTP 다운로드를 시작하고 완성된 사본만 목적지로 전달한다. 기존 파일을 덮어쓰지 않으며 실패한 임시 전달 폴더를 정리한다. 마지막 창을 닫을 때 진행 중인 전달도 기다린다.
- macOS 네이티브 모듈은 Node-API로 분리했다. 다른 운영체제는 기존 HTML 전송과 사전 다운로드 내보내기를 사용한다. 네이티브 테스트 모듈은 배포 앱에 포함하지 않는다.
- README를 작업 순서 중심으로 다시 작성하고 현재 UI의 공개 데모 스크린샷 3장을 추가했다. 상세 사용법과 배포 절차를 별도 문서로 옮겼다.
- 개인 Developer ID Application 인증서로 macOS arm64 앱 전체를 서명했다. Hardened Runtime과 JIT 권한을 적용했고 `codesign --verify --deep --strict` 검증이 통과했다. 서명된 Electron 런타임에서 배포용 네이티브 드래그 모듈의 로딩도 확인했다.
- 키체인 프로필을 사용하는 서명·공증·검증 스크립트를 추가했다. 2026-09-23 Apple 공증이 `Accepted`로 완료됐으며 공증 티켓 첨부·검증, 코드 서명 무결성, Gatekeeper의 `Notarized Developer ID` 판정을 확인했다. 앱 암호는 Bitwarden과 로컬 키체인에 보관하며 저장소·배포 파일에 포함하지 않는다.
- macOS Apple Silicon용 0.5.1은 프리뷰로 배포한다. 원격→Finder의 최종 실기 확인과 Windows 검증이 남아 있다는 점을 README와 릴리스 안내에 명시한다.
- 단위·SSH 통합 테스트 48개와 Electron 시나리오 11개가 통과했다. 원격 편집 테스트의 임시 경로 부재 재시도 누락을 보완했다. 네이티브 테스트는 AppKit 수신 형식 인식, provider delegate의 실제 SSH 다운로드, 파일·폴더 전달, 충돌 보존, 서버 파일 소실의 오류 전달까지 검사한다.
- 실제 창에서 네이티브 드래그 세션 시작을 확인했다. 컴퓨터 제어 도구로 Finder에 최종 마우스 놓기를 전달하지 못했으므로 Finder의 최종 놓기는 별도 수동 확인이 필요하다. 이 제한을 자동 테스트 통과로 대체하지 않는다.

## 0.5 창과 외부 파일 연동

- 독립 창과 새 창 단축키를 추가했다. 창별 탐색·선택을 유지하고 연결·전송·편집·파일 클립보드를 공유한다. 한 창을 닫아도 다른 창의 연결을 종료하지 않는다. 마지막 창에는 기존 전송·편집 보호 절차를 적용한다.
- 로컬 파일의 네이티브 외부 드래그, Sinder 창 사이 복사·Shift 이동, Finder/Explorer 파일의 패널·폴더 드롭을 연결했다. 원격 항목은 사본을 준비한 뒤 외부 드래그를 시작한다. 실패한 준비는 해당 임시 배치만 정리하며 서버 원본을 유지한다.
- 더블 클릭·Enter는 파일 열기, Space는 미리보기다. 원격 텍스트는 기존 자동 반영·충돌 복구 편집기로 열고, 지원 문서는 기본 앱에서 사본으로 연다. 실행 파일은 연결 앱으로 자동 실행하지 않는다.
- 숨김 파일 토글을 창 사이에서 동기화하고 Finder 방식의 `⌘ Shift .`도 지원한다. 숨김 판단은 점으로 시작하는 이름 기준이며 Windows의 별도 Hidden 속성 조회는 포함하지 않는다.
- 단위·실제 SSH 통합 테스트 48개 통과. Electron 시나리오 10개 통과(기존 7개, 새 창·외부 드래그·원격 문서 3개). 네이티브 드래그의 자동 검증은 실제 파일 준비와 발신 창 검증 및 `startDrag` 인수 전달까지이며, Finder/Explorer의 최종 놓기 동작은 수동 검증 범위다. Windows 실기 검증은 남아 있다.
- TypeScript·빌드·포맷 검사가 통과했다. macOS arm64 0.5.0 패키지의 빌드 파일과 드래그 아이콘 17개가 소스 빌드와 일치하며 ad-hoc 코드 서명 검사가 통과했다. 배포용 서명과 공증은 포함하지 않는다.
- 설치 패키지를 격리된 앱 데이터 경로로 실행해 `app.isPackaged=true`, 0.5.0과 독립 창 2개를 확인했다. 기존 macOS 설치본은 이전 앱을 보관한 뒤 교체했다.

0.4의 `electron-builder --mac dir` 패키징과 `codesign --verify --deep --strict` 검증이 완료됐다. 패키지에 포함된 빌드 파일 15개는 최종 빌드와 바이트 단위로 일치한다. 산출물 `release/mac-arm64/Sinder.app`과 설치본 `~/Applications/Sinder.app`의 ASAR SHA-256은 동일하다. 이전 버전은 별도로 보존했다.

## 후속 확장과 검증 범위

현재는 로컬·SSH 통합 탐색, 원격 편집 복구와 컴팩트 UI에 로컬 SSH 설정 가져오기를 추가한 0.4 버전이다. macOS 우선 실행과 Windows 확장 구조라는 요청 범위로 구현했으며, 아래는 후속 확장과 운영 환경 검증 항목이다.

1. 원격 파일 외부 편집·자동 반영, 충돌 비교·명시적 재적용, 서버 이전 버전 보존, 오프라인 수정본과 앱 재시작 복구는 0.2에서 구현·검증했다. 다음에는 긴 연결 중 실제 편집기별 저장 동작과 대용량 파일을 추가 검증한다.
2. 재연결 시 기존 패널 경로·이동 기록을 유지하고, 연결되지 않은 즐겨찾기의 목적 경로를 연결 후 사용한다. 파일 전송 큐의 앱 재시작 복원과 중단된 전송 재개는 아직 남아 있다.
3. SSH config 가져오기·자동 입력과 ProxyCommand/ProxyJump 경유 연결은 0.4에서 구현했다. 조건부 Match, 인증서와 다중 키 순차 인증 등 전체 OpenSSH 호환은 후속 범위다.
4. 큰 폴더의 렌더링과 재귀 검색. 현재 검색은 폴더 내 이름 필터다.
5. 사용자 실서버·대용량 파일·장시간 연결 사용 검증. 기존 테스트는 임시 키를 쓰는 로컬 OpenSSH 서버다.
6. 배포용 코드 서명/공증과 Windows 실기 검증. 개발 빌드는 ad-hoc 서명을 사용한다.

## 0.2 검증 기록

- 통합/회귀 테스트: 기존 파일 작업 6개 + 원격 편집 8개 + 로컬 복구 파일 기록 3개, 총 17개 통과. 255바이트 파일 이름, 업로드 임시 이름 충돌, 동시 복원과 디스크 쓰기 실패도 검사했다.
- `npx playwright test`: 로컬 탐색, SSH 전송/휴지통/복원, 외부 편집 흐름/충돌/재연결/앱 재시작의 3개 시나리오 통과.
- 저장 완료 응답 유실, 원본 이름 변경 직후 연결 단절, 두 이름 변경 순간의 외부 작성자 경쟁, 동일 크기·수정 시간의 서버 변경을 실제 OpenSSH 파일로 검사했다.
- 편집기가 캐시를 지운 상태에서도 서버 원본을 먼저 복구한다. 서버에 남은 유효한 임시 수정본은 완전히 기록한 로컬 임시 파일에서 배타적으로 게시하여 복원하며, 동시에 생성된 편집기 파일은 덮어쓰지 않는다. 서버 경로에 다른 작성자가 파일을 다시 만든 경우도 검사했다.
- 캐시는 `userData/remote-edits`에 보존한다. 파일 콘텐츠 SHA-256과 서버·계정·호스트 키 식별자를 기준으로 반영한다. 백업은 `.sinder-edit-<ID>/<name>`에 보관하며 자동 삭제하지 않는다.
- 쓰기 전 복구 기록을 디스크에 flush하고 macOS/POSIX에서는 부모 디렉터리도 동기화한다. Windows에서는 Node의 디렉터리 동기화를 사용하지 않으며 실기 검증은 남아 있다. 원본과 수정본의 두 단계 이름 변경은 원래 경로가 잠시 없을 수 있으며, 공동 편집 분산 잠금이나 원자적 파일 시스템 트랜잭션으로 표시하지 않는다.
- 같은 앱 데이터 폴더를 쓰는 중복 앱 실행을 막아 편집 캐시와 복구 기록에 두 프로세스가 동시에 쓰지 않도록 했다.

## 0.3 검증 기록

## 0.4 로컬 SSH 설정

- 사용자 홈의 `.ssh/config`와 Include를 읽어 연결 필드를 자동 입력하고, 지원되는 대표 호스트를 접속 없이 일괄 저장한다. 같은 Host의 여러 별칭과 재가져오기의 중복을 막으며 기존 프로필·즐겨찾기를 유지한다.
- 로컬 설정을 읽기 전용으로 확인하여 대표 호스트와 프록시 경로 인식을 검증했다. 개인 설정과 키는 저장소에 포함하지 않는다.
- ProxyCommand 실행 파일과 ProxyJump 경유 연결을 지원한다. 가져오기에서는 명령을 실행하지 않고, 실제 연결에서만 로컬 설정의 경로를 사용한다. 지원하지 않는 조건·셸 구문은 가져오기 화면에 표시한다.
- 단위·통합 테스트 47개와 Electron 시나리오 7개가 통과했다. OpenSSH와 대조한 Include 조건 복귀, ID 재사용·중복 방지 보완 후 관련 8개 테스트를 재검증했다. 실제 임시 서버의 프록시 SFTP·경유 연결·취소·프로세스 종료를 포함한다.
- 사용법과 지원 경계는 [SSH 설정 가져오기](SSH-CONFIG.md)에 기록했다. Windows 실기 검증과 사용자 서버의 실제 접속은 포함하지 않는다.
- 설치본에서 로컬 호스트 가져오기와 프록시 설정·기존 항목 보존·재가져오기 중복 방지·가져오기 중 서버 미접속을 확인했다. 실제 앱 화면을 검토하고 디버그 인수 없이 다시 실행했다.
- 0.4 패키지 빌드 파일 15개가 최종 산출물과 일치하고 ad-hoc 코드 서명 검사가 통과했다. ASAR 7,739,789 bytes, SHA-256 `50ea602e94b4d1b357030aa27caf7c66ea83d415605ce6dce9a194a94afae9fd`. 이전 0.3 앱은 별도 보존했다.
